# Detailed functionalities

This document lists the functionalities of TrainFyre, classified by priority and by type of user, and states which ones are implemented in version 0.1. The original Phase 1 definition is preserved in [Initial functionalities](INITIAL_FUNCTIONALITIES.md). The implemented behaviour is illustrated in [Features of version 0.1](FEATURES.md).

Status legend:

- **Implemented**: available in version 0.1 and described as it behaves.
- **Partial**: only part of the definition is available.
- **Pending**: not implemented yet.

## Basic functionality

### For anonymous users

| Functionality | Status | Current behaviour |
| --- | --- | --- |
| Access public information about transport lines | Partial | The public incidence list and detail pages show the map and line identifiers affected by each incidence. There is no catalogue of maps and lines yet. |
| Consult the general status of the monitored network | Partial | The status is obtained from the list of incidences, which can be filtered by map, line, severity, cause and date range. There is no summary dashboard. |
| Register a new account | Implemented | Registration form with username (3 to 32 characters) and password (12 to 128 characters). The account receives the `USER` role and the user is signed in automatically. |

### For registered users

| Functionality | Status | Current behaviour |
| --- | --- | --- |
| Sign in and sign out | Implemented | Username and password produce a JWT access token that expires after 15 minutes. The session lasts while the browser tab is open. |
| Manage the profile and the profile picture | Implemented | The user can change the username and password, delete the account, and upload, replace or delete an avatar (PNG, JPEG or WebP, up to 2 MB). |
| Create and update alert subscriptions | Implemented | A subscription stores lines, a time window, days of the week and an optional expiration. Subscriptions can be added, edited and deleted. |
| Receive notifications for the lines of interest | Pending | Subscriptions are stored but no notification is sent through any channel. |

### For administrators

| Functionality | Status | Current behaviour |
| --- | --- | --- |
| Manage the entities of the application | Partial | Incidences can be created, edited and deleted. Users can be created from the administration page. Maps and lines do not exist as entities yet. |
| Review system-level statistics and content generated by users | Pending | Not available. |
| Maintain the operational data of the platform | Partial | Limited to the incidences. |

## Intermediate functionality

| Functionality | Status | Current behaviour |
| --- | --- | --- |
| List incidents with status, timing, and affected lines | Implemented | The table shows name, affected map and lines, severity, duration or delay and date, with 10 incidents per page. |
| Filter incidents by map, line, or time window | Implemented | Filters by map identifier, line identifier and date range, plus free text, severity and cause. |
| Display charts related to incident statistics and usage trends | Pending | Not available. |
| View summaries of transport alerts in a user-friendly interface | Partial | Incident detail page with description, severity, cause, date, duration and affected lines. There are no aggregated summaries. |

Listing and filtering incidents were classified as intermediate in Phase 1 but were implemented in this version because they are the core of the application.

## Advanced functionality

The advanced functionality is still under analysis and may evolve based on the final requirements and technical constraints. No advanced features have been implemented or planned yet.

## Role matrix

| Priority | Anonymous | Registered | Admin |
| --- | --- | --- | --- |
| Basic | Register in the system (implemented); general public status (partial) | Sign in and out, profile management and subscriptions (implemented); notifications (pending) | CRUD of incidences and creation of users (partial); statistics (pending) |
| Intermediate | Public incident list, filters and detail (implemented); charts (pending) | Same as anonymous users | Publish, edit and delete incidences (implemented) |
| Advanced | Not yet defined | Not yet defined | Not yet defined |

## Permissions implemented in the backend

| Operation | Anonymous | Registered user | Administrator |
| --- | --- | --- | --- |
| Register, sign in | Yes | Yes | Yes |
| List incidences | Yes | Yes | Yes |
| Get an incidence by identifier through the API | No | No | Yes |
| Create, update, delete incidences | No | No | Yes |
| Read, update, delete a user account | No | Own account only | Own account only |
| Upload, read, delete an avatar | No | Own avatar only | Any avatar |

The web interface obtains the detail of an incidence for non-administrators from the public list, so detail pages are visible to everyone.
